*tl;dr: AI Software Engineers are coming faster than you think. Spend some time trying the new tools now since they’ll be your colleagues in the future.*

I have a confession. I have been an AI skeptic for a long time. In college, I had friends taking machine learning courses but I assumed ML would be confined to flying model helicopters in novel ways and labeling emails as spam.

I was wrong.

I now believe AI is going to completely alter the way we interact with computers. ~~It will be the biggest platform shift we have experienced in our lifetimes: bigger than mobile, bigger than the shift to cloud, bigger than the Internet itself.~~

Let me share how I arrived here.

It started with my exploration into AI software engineers.

## A Personal Anecdote

Last year I started a company with my friend, Jet. We’ve explored multiple business angles, as is common for a startup, and so most of the programming I do is quick prototyping.

My default workflow is:
1. Think of an idea
2. Fire up Zed
3. Chat with Claude to produce the first version of my program
4. Run the output
5. Feed the errors back into Claude
6. Repeat until the program is working

Claude is my compiler, my pair programmer and my conversational partner all in one.

However, steps 4, 5 and 6 can get tedious.

I often find myself copying entire API definitions into Claude and informing it of new libraries or versions when it uses something outdated. I feed it byzantine Typescript errors (for the love of god, who is responsible for this? *example of Typescript error) ad nauseam until I hit diminishing returns and ask Jet for help.

That experience led me to prototype a Typescript compiler wrapper that fed errors into Claude and gave me a natural language explanation of their cause.

Which eventually led me to explore AI software engineers.

## AI SWEs
By now you’ve surely heard of Devin: the canonical example of an AI software engineer.

What you might not have heard of is OpenHands: an open source alternative.

Convinced that I could rely on Claude itself to run steps 4, 5 and 6, I booted up OpenHands.

And it works!

I can describe a task to OpenHands and it will execute the task entirely by itself, using a terminal, a web browser and a Python notebook.

It’s also working for OpenHands itself: you can see the contributions it’s made to its own codebase here. The company behind OpenHands, AllHands, is a team of industry veterans, computer science PhDs and a computer science professor. They’re serious about their craft and they’re benefiting from working directly with an AI SWE.

In a few years, all software engineers will be working with AI colleagues.

## From AI SWE to AGI
As I realized that AI SWEs are already among us, I became more and more convinced that we will achieve AGI.

My base assumption since college has been that writing software would be impossible for computers. Sure deterministic code modifications could produce large amounts of code.

But actually writing useful software would always be the province of software engineers.

My base assumption was wrong.

Soon, anyone will be able to write software. It will no longer be “technical” people who write software. It will be everyone.

## What needs to change
There are bunch of implications the true democratization of software.

A few of the most interesting questions that will effect software engineers first are:
* How will we review code when it’s generated faster than a human can read it? (screenshot from OpenHands)
* How will we prompt models? Will there be a language for “programming models” with the LLM as a “natural language” compiler?
* How will we run these agents? Will they be centralized (run by Anthropic or OpenAI or others) or part of each company’s cloud infra?

## Where to go from here
Try the tools!

For any software engineer today, trying the latest AI tools is imperative. The profession is in transition from writing craft lines of code to orchestrating AI systems that build and maintain software.

It’s easy to get started with Cursor Compose or run OpenHands locally.
